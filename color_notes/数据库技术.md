# 数据库技术：重点与易错

## 第1章 数据库系统概论

### 数据库、DBMS与三级模式
- 🔴 **核心知识**：DB 是有组织的数据集合，DBMS 负责定义、存取与控制，DBS 还包括应用、人员和环境；外模式、模式、内模式依次描述用户视图、全局逻辑和物理存储。
- 🔵 **方法与例题**：遇到数据独立性题先找“改了什么”：表的逻辑结构变化而程序少改是逻辑独立性，文件组织变化而逻辑表不变是物理独立性。
- ⚫ **易混易错**：数据库不等于数据库系统，模式也不等于某个用户看到的外模式；一个数据库通常有一个模式、一个内模式和多个外模式。

## 第2章 概念模型与E-R方法

### E-R建模
- 🔴 **核心知识**：E-R 图用实体、属性和联系描述业务；联系的 1:1、1:n、m:n 要从两个方向分别判断最大对应数量，并标清参与约束。
- 🔵 **方法与例题**：把“学生可选多门课、课程可被多名学生选”拆成两个方向提问，可知是 m:n；若选课还有成绩，成绩应作为联系属性。
- ⚫ **易混易错**：业务名称相同不代表同一实体，多值属性不能塞进一个原子字段；基数由业务规则决定，不能只看当前样例数据。

### E-R转关系
- 🔴 **核心知识**：实体通常各转一张表；1:n 把“1”端主键放到“n”端作外键，m:n 必须新建联系表，联系属性也放入该表。
- 🔵 **方法与例题**：学生与课程的选课联系转为 Enrollment(student_id,course_id,score)，联合主键防止同一学生重复选同一门课。
- ⚫ **易混易错**：1:n 的外键不能放反；m:n 只在一端增加单个外键会丢失多个对应关系，1:1 还要结合全参与和空值选择放置端。

## 第3章 关系模型与完整性

### 关系键与完整性
- 🔴 **核心知识**：候选码是最小超码，主码从候选码中选定，外码引用另一关系的候选码；实体、参照、用户定义完整性分别约束标识、引用和业务规则。
- 🔵 **方法与例题**：判候选码先验证能否唯一决定全部属性，再逐个删除属性检查最小性；外码值必须为空或等于被引用表中已存在的键值。
- ⚫ **易混易错**：唯一并不自动满足最小性，主码不是唯一可能的候选码；NULL 既不等于 0 也不等于空串，判断它要用 IS NULL。

## 第4章 关系代数

### 关系代数
- 🔴 **核心知识**：选择取行、投影取列，连接按条件组合元组；并、交、差要求并相容，除法表达“对给定集合中的所有对象都满足”。
- 🔵 **方法与例题**：查询“选了全部必修课的学生”可用选课关系除以必修课程集合；复杂表达式先选择缩小行，再连接，最后投影目标列。
- ⚫ **易混易错**：投影按集合语义去重；自然连接会匹配全部同名属性，同名但含义不同会误连，漏写连接条件则变成笛卡尔积。

## 第5章 关系数据库标准语言SQL

### SQL定义与约束
- 🔴 **核心知识**：DDL 定义对象，DML 修改数据，DQL 查询，DCL 控制权限；PRIMARY KEY、FOREIGN KEY、UNIQUE、NOT NULL、CHECK 表达不同约束。
- 🔵 **方法与例题**：建学生表时先定字段类型，再用主键保证学号唯一非空，用外键引用院系，用 CHECK(age>=0) 拦截非法年龄。
- ⚫ **易混易错**：DELETE 删除行，DROP 删除对象定义，TRUNCATE 的事务行为依 DBMS 而定；外键列可以重复，能否为空取决于额外约束。

### SQL筛选、分组与聚合
- 🔴 **核心知识**：逻辑处理通常按 FROM、WHERE、GROUP BY、HAVING、SELECT、ORDER BY；WHERE 筛行，HAVING 筛组，聚合函数对一组行求值。
- 🔵 **方法与例题**：统计成年学生不少于 5 人的院系：先 WHERE age>=18，再 GROUP BY dept_id，最后 HAVING COUNT(*)>=5。
- ⚫ **易混易错**：COUNT(*) 统计行而 COUNT(列) 忽略该列 NULL；未分组的普通列不能随意与聚合结果同时出现在 SELECT 中。

### 连接、子查询与集合运算
- 🔴 **核心知识**：内连接只保留匹配行，外连接还保留一侧未匹配行；相关子查询依赖外层当前行，EXISTS 判断是否存在，IN 判断成员关系。
- 🔵 **方法与例题**：先画主外键路径并写连接后的行；要保留未借书读者用LEFT JOIN，计借阅数用COUNT(b.book_id)，不能让COUNT(*)把补NULL行算成1本。
- ⚫ **易混易错**：LEFT JOIN 后在 WHERE 中限制右表列可能把外连接变成内连接；NOT IN 遇到 NULL 会产生未知结果，常优先使用 NOT EXISTS。

## 第6章 视图、索引与数据库设计

### 视图
- 🔴 **核心知识**：视图保存查询定义并提供逻辑封装、权限隔离和一定的数据独立性；普通视图通常不单独存结果，可更新性受连接、聚合等操作限制。
- 🔵 **方法与例题**：给辅导员只开放本院学生必要列，可建限定院系和列的视图并授权；判断可更新性先看一行视图能否唯一对应一行基表。
- ⚫ **易混易错**：视图不等于物化视图，也不天然提高查询速度；删除视图通常不删除基表数据，但依赖该视图的对象可能受影响。

### 索引与物理设计
- 🔴 **核心知识**：索引用额外空间和写维护成本换查询定位速度；B+树适合等值、范围与有序扫描，组合索引能否使用取决于列顺序和查询条件。
- 🔵 **方法与例题**：订单号等值查询适合唯一索引，按下单时间范围筛选和排序适合有序索引；设计时同时检查选择性、读写比例和覆盖情况。
- ⚫ **易混易错**：索引不是越多越好，低选择性字段单独建索引未必有效；组合索引 (a,b) 通常不能直接等价为只按 b 高效查找。

### 数据库设计流程
- 🔴 **核心知识**：设计依次经历需求分析、概念设计、逻辑设计、物理设计、实施和运行维护；阶段产物从业务需求、E-R图、关系模式逐步落到索引与存储结构。
- 🔵 **方法与例题**：看到“画实体联系”判概念设计，“把E-R转成表并规范化”判逻辑设计，“选择索引和文件组织”判物理设计。
- ⚫ **易混易错**：设计阶段不是完全割裂的直线，验证后可能回退修改；索引选择属于物理设计，不能拿它代替关系模式和完整性设计。

## 第7章 关系数据理论

### 属性闭包与候选键
- 🔴 **核心知识**：属性集 X 的闭包 X⁺ 是由函数依赖能推出的全部属性；X⁺覆盖关系全部属性时X是超码，再逐个删除属性仍不能覆盖全部时才是候选键。
- 🔵 **方法与例题**：对F={A→B，B→C，AD→E}，从AD出发反复加入B、C、E，得(AD)⁺=ABCDE；删A或D都不完整，所以AD是候选键。
- ⚫ **易混易错**：样例数据暂时唯一不能证明函数依赖；求闭包要反复扫描依赖直到不再增长，超码还必须继续检查最小性才能称候选键。

### 范式判断
- 🔴 **核心知识**：2NF消除非主属性对候选键的部分依赖，3NF限制非主属性的传递依赖；形式上3NF允许右部是主属性，BCNF则要求每个非平凡依赖的决定因素都是超码。
- 🔵 **方法与例题**：R(学号,课程号,姓名,成绩)中(学号,课程号)是码，学号→姓名是部分依赖，故不满足2NF；先找全部候选键再判主属性。
- ⚫ **易混易错**：单属性候选键不会产生对该键的部分依赖；不能只检查所选主键，3NF和BCNF判断必须考虑全部候选键及函数依赖。

### 分解、无损连接与依赖保持
- 🔴 **核心知识**：分解后自然连接应恰好恢复原关系才无损；二元分解R→R1、R2若公共属性能函数决定R1或R2，则可判无损，依赖保持要求分表内依赖可推出原依赖。
- 🔵 **方法与例题**：把R(A,B,C)按A→B分成R1(A,B)、R2(A,C)，公共属性A能决定R1全部属性，因此无损，A→B也可在R1直接检查。
- ⚫ **易混易错**：无损连接与依赖保持是两个不同目标；能查回数据不代表全部约束能在单表检查，分表过细还可能增加连接成本。

## 第8章 事务、并发控制与恢复

### ACID与事务边界
- 🔴 **核心知识**：原子性要求全做或全不做，一致性保持约束，隔离性限制并发干扰，持久性保证提交结果不因故障丢失；提交和回滚确定事务边界。
- 🔵 **方法与例题**：借书记录写入与库存减一必须放在同一事务中，任一步失败都回滚；答题时把具体风险对应到 ACID，而非只背四个名称。
- ⚫ **易混易错**：一致性是业务约束满足的结果，不等于多个副本立刻相同；自动提交会缩短事务边界，长事务则更容易持锁并阻塞他人。

### 并发异常与隔离级别
- 🔴 **核心知识**：脏读看未提交值，不可重复读看同行值变化，幻读看条件行集变化；隔离级别控制可见干扰。
- 🔵 **方法与例题**：先标每次读写与提交时点，再判断异常；读已提交排脏读，但仍可重复读到已改变的行值。
- ⚫ **易混易错**：产品的锁与多版本实现不同，不能把可重复读对幻读的细节一概而论，也不能用事务代替业务幂等。

### WAL与恢复
- 🔴 **核心知识**：WAL 要求数据页写盘前相关日志先稳定写入；日志记录更新前后信息，检查点缩短恢复扫描，恢复阶段按提交状态重做或撤销。
- 🔵 **方法与例题**：系统故障后，已提交但数据页未落盘的更新需要 REDO，未提交却已落盘的更新需要 UNDO；先看日志顺序再判断事务状态。
- ⚫ **易混易错**：COMMIT 成功依赖提交日志持久化，不要求所有数据页立即落盘；备份解决介质损坏，日志恢复主要处理事务和系统故障，两者不能互相替代。

### 冲突优先图判串行化
- 🔴 **核心知识**：不同事务在同一数据上至少一个写才冲突，按出现先后连Ti→Tj；图无环则冲突可串行化。
- 🔵 **方法与例题**：r1(X)、w1(X)、r2(X)、w2(X)只给T1→T2，故可按T1后T2串行；若另有反边便成环。
- ⚫ **易混易错**：两个读操作不冲突；要检查所有数据项上的边，不能只看一个数据的顺序就宣布整个调度无环。

### 两段锁的首次解锁
- 🔴 **核心知识**：增长阶段只加锁不解锁，首次解锁后进入收缩阶段，此后只能释放，不能再申请新锁。
- 🔵 **方法与例题**：加锁A、加锁B、解锁A、再加锁C违反2PL；应在首次解锁之前取得所需新锁或重新设计事务。
- ⚫ **易混易错**：2PL保证冲突可串行化却仍可能死锁；严格2PL把排他锁留到提交或回滚，不能混为无锁快照。

## 第9章 数据库安全性

### 认证、授权与审计
- 🔴 **核心知识**：认证确认身份，授权决定可做什么，审计记录做过什么；权限应按最小权限原则授予，角色用于集中管理一组权限。
- 🔵 **方法与例题**：GRANT授权、REVOKE回收；只有对象所有者、管理员或获WITH GRANT OPTION者可转授，回收时还要沿授权链检查级联影响。
- ⚫ **易混易错**：通过登录不等于拥有全部权限，角色权限和直接授权要分别检查；备份、加密、授权和审计分别解决不同风险。
