# 数据库技术：重点与易错

## 第1章 数据库系统概论

### 数据库、DBMS与三级模式

- 🔴 **核心知识**：DB是长期存储、有组织、共享的数据集合；DBMS是管理软件，DBS是数据/软件/人员/环境整体；DBA负责管理。
- 🔵 **方法与例题**：外模式=用户局部视图，模式=全局逻辑结构，内模式=物理结构；外/模式映像支持逻辑独立，模式/内映像支持物理独立。
- ⚫ **易混易错**：逻辑独立不等于所有结构修改都无需改应用；数据库降低冗余，不消灭所有重复。

### 键值数据的写入与读取

- 🔴 **核心知识**：键值模型按唯一键定位一个值，本例PUT同键替换整值，GET按键读取；对象字段可装在值中但不自动形成字段查询。
- 🔵 **方法与例题**：PUT user:7为姓名/城市后GET得两字段；再PUT同键仅city长沙，GET只有city，不会自动保留旧name。
- ⚫ **易混易错**：语义按本例约定而非产品通则；需保旧字段要明确合并，并发要防丢失更新；不能由GET推断支持任意字段索引。

### 文档数据的字段筛选

- 🔴 **核心知识**：文档模型以字段组织对象，可按字段条件筛选；本例INSERT建文档，UPDATE只改指明字段，FIND返回匹配者。
- 🔵 **方法与例题**：两文档id1邵阳20岁、id2长沙22岁：按city邵阳得id1；将id1年龄改21后，姓名和城市不变。
- ⚫ **易混易错**：字段筛选不保证已有索引，无索引可能扫描；缺失字段与NULL规则依实现，文档模型也需约束和更新维护。

## 第2章 概念模型与E-R方法

### E-R建模

- 🔴 **核心知识**：实体—联系（E-R）模型以实体、属性、联系描述现实；实体型定义结构，实体集是同型实体集合。
- 🔵 **方法与例题**：先问两个方向最多对应几个确定1:1/1:n/m:n，再问是否必须参与；矩形实体、椭圆属性、菱形联系。
- ⚫ **易混易错**：联系基数与参与约束不同；一个实体实例不等于实体型，“每次借阅日期”属于具体借阅。

### E-R转关系

- 🔴 **核心知识**：实体型通常转表；1:n把1端码放n端作外码；m:n独立联系表包含双方码及联系属性。
- 🔵 **方法与例题**：同一学生每门课只记录一次时，SC的(sid,cid)可作联合码；重复借同一本书则需借阅编号等事件标识。
- ⚫ **易混易错**：双方码不必总能唯一识别重复事件；1:1外码还需唯一约束，多值属性另表，不能把m:n硬存单个外码。

## 第3章 关系模型与完整性

### 关系键与完整性

- 🔴 **核心知识**：关系为元组集合，属性取值来自域；候选码=最小超码，主码是选中的候选码，主属性属于任一候选码。
- 🔵 **方法与例题**：主码唯一非空=实体完整性；外码符合引用规则=参照完整性；分数范围等=用户定义完整性。
- ⚫ **易混易错**：最小是无多余属性，不是长度最短；SQL表可重复，理论关系不可重复；外码不自动非空。

## 第4章 关系代数

### 关系代数

- 🔴 **核心知识**：选择σ筛行、投影π取列去重，连接组合元组；并/差/交要求并相容，除表达“对所有”。
- 🔵 **方法与例题**：R(X,Y)÷S(Y)保留与S全部Y配对的X；若R={(1,A),(1,B),(2,A)}、S={A,B}，结果{1}。
- ⚫ **易混易错**：自然连接按全部同名列相等并去重列，不是任意两表直接拼；有一门不等于所有门。

## 第5章 关系数据库标准语言SQL

### SQL定义与约束

- 🔴 **核心知识**：SQL为结构化查询语言；DDL定义结构，DML广义含查询/更新，也可单列SELECT为DQL；GRANT/REVOKE控制权限。
- 🔵 **方法与例题**：PRIMARY KEY(a,b)保证组合唯一且均非空；CHECK(score BETWEEN 0 AND 100)还需NOT NULL才强制必填。
- ⚫ **易混易错**：DELETE删行、DROP删对象，TRUNCATE保留表定义但事务细节依DBMS；CHECK通常容许UNKNOWN。

### SQL筛选、分组与聚合

- 🔴 **核心知识**：逻辑上FROM/JOIN→WHERE→GROUP BY→HAVING→SELECT→ORDER BY；只在明确排序时保证结果顺序。
- 🔵 **方法与例题**：先WHERE筛成年，再按部门分组，HAVING COUNT(*)>=2筛组；COUNT(*)数行，COUNT(列)忽略NULL。
- ⚫ **易混易错**：聚合条件不能直接放WHERE；SELECT默认保留重复，DISTINCT才去重；=NULL应改IS NULL。

### 连接、子查询与集合运算

- 🔴 **核心知识**：内连接留匹配，左连接留全部左行、未匹配右列补NULL；IN看成员，EXISTS看有无行。
- 🔵 **方法与例题**：Reader1借两本、Reader2未借，LEFT JOIN共3行；COUNT(b.book_id)得2/0，COUNT(*)会给未借者1。
- ⚫ **易混易错**：WHERE过滤右表列可能删掉补NULL行；NOT IN子查询含NULL可能出现UNKNOWN，NOT EXISTS须写相关条件。

### 存储过程的一次参数调用

- 🔴 **核心知识**：存储过程按名称接参数，在数据库内执行条件与数据操作并返回结果；调用结果与表的变化应分别核对。
- 🔵 **方法与例题**：余额80调用扣款(7,30)：查账户→检金额/余额→更新50→返回成功；独立从80扣90在检查处返回不足，值不变。
- ⚫ **易混易错**：示例伪码不绑定产品语法；过程不自动解决并发，实际仍须事务/原子更新或锁，并检查权限与影响行数。

### 游标的逐行读取与关闭

- 🔴 **核心知识**：游标用于逐行获取查询结果，OPEN后反复FETCH并检查有没有行，只有取到新行才处理，结束或异常需清理。
- 🔵 **方法与例题**：成绩80/90：sum从0到80到170；第三次FETCH无行先退出再CLOSE，不能把上次score90重复加到260。
- ⚫ **易混易错**：空结果第一取即结束；NULL/可见性按约定，能用集合SQL求和时优先集合处理，不因逐行写法更长就更正确。

## 第6章 视图、索引与数据库设计

### 视图

- 🔴 **核心知识**：普通视图为查询定义的虚表，通常不保存结果；物化视图保存结果并需维护/刷新。
- 🔵 **方法与例题**：用CREATE VIEW v AS SELECT sid,name FROM Student WHERE dept=10定义局部视图，再按视图授权。
- ⚫ **易混易错**：可更新性依定义及DBMS，聚合/分组视图通常不能直接逐行更新；视图不是物理索引。

### 索引与物理设计

- 🔴 **核心知识**：索引是额外存取结构；B+类有序索引支持等值/范围，散列类主要等值；写入须维护。
- 🔵 **方法与例题**：(a,b)顺序(1,2),(1,8),(2,1),(2,9)：a=2定位后段，再b=9缩小；仅b=9跨a分散。
- ⚫ **易混易错**：不以“有索引”断言一定用；大结果集、表达式及成本可使优化器选扫描，唯一约束与性能结构不同。

### 数据库设计流程

- 🔴 **核心知识**：需求→概念设计→逻辑设计→物理设计→实施→运行维护。
- 🔵 **方法与例题**：概念阶段E-R，逻辑阶段关系模式/约束及规范化，物理阶段记录存储、索引和访问路径；实施建库装数据并测试。
- ⚫ **易混易错**：索引不能修补错误实体关系；关系表划分不是物理文件布局。

### 查询执行与优化

- 🔴 **核心知识**：解析语义检查→逻辑改写→选物理计划→执行；存储管理按页读取，优化看中间结果和I/O代价。
- 🔵 **方法与例题**：内连接可先筛Student的CS行再连SC，减少中间行；等值连接可散列，已按键有序可归并。
- ⚫ **易混易错**：不能任意下推外连接条件；索引存在不保证成本最低，统计过时可误估。

## 第7章 关系数据理论

### 属性闭包与候选键

- 🔴 **核心知识**：X⁺是根据F可由X推出的全部属性；X⁺含全部属性则X为超码，进一步最小才是候选码。
- 🔵 **方法与例题**：R(ABCDE),F={A→B,B→C,AD→E}：AD→ABD→ABCD→ABCDE；删A或D均推不全，故AD是候选码。
- ⚫ **易混易错**：必须反复扫描到不增长；一个超码求出后不能跳过最小性检验；依赖来自业务约束。

### 范式判断

- 🔴 **核心知识**：1NF属性原子；2NF非主属性完全依赖每一候选码；3NF每非平凡X→A满足X超码或A主属性；BCNF均要求X超码。
- 🔵 **方法与例题**：R(sid,cid,name,score)，sid→name，sid,cid为候选码，name对码部分依赖，故不满足2NF。
- ⚫ **易混易错**：主属性属于任一候选码；不是只有主码。单属性候选码也可能有传递依赖，仍须查3NF。

### 分解、无损连接与依赖保持

- 🔴 **核心知识**：无损连接使投影再连接恰好还原合法关系；依赖保持使分表约束合起来可推出原依赖。
- 🔵 **方法与例题**：函数依赖下二元分解：公共属性能决定某一分表全部属性则无损。R(ABC),A→B，拆AB/AC，公共A决定AB。
- ⚫ **易混易错**：无损不自动保持所有依赖，保持依赖也不自动无损；分解不是越细越好。

### 多值依赖与4NF

- 🔴 **核心知识**：X↠Y表示固定X后Y集合与剩余Z集合独立；4NF要求每个非平凡多值依赖的决定项是超码。
- 🔵 **方法与例题**：学生甲爱好棋/球、语言中/英且独立，原表4组合；拆学生-爱好、学生-语言消去组合冗余。
- ⚫ **易混易错**：不独立不能强拆再取全部组合；4NF比只检查函数依赖更强。

## 第8章 事务、并发控制与恢复

### ACID与事务边界

- 🔴 **核心知识**：事务是用户定义的操作序列及逻辑工作单位；原子性、一致性、隔离性、持久性（ACID）共同约束执行。
- 🔵 **方法与例题**：转账扣款/入账一起提交；失败回滚。COMMIT确认逻辑结果，不要求全部数据页立刻写回，须满足日志持久化协议。
- ⚫ **易混易错**：事务不自动保证错误业务程序正确；持久性还需日志/备份和故障模型支持。

### 并发异常与隔离级别

- 🔴 **核心知识**：脏读=未提交数据；不可重复读=同一行值被他事务提交修改；幻读=谓词结果集合变化；丢失修改=写覆盖。
- 🔵 **方法与例题**：标准最小要求：读已提交防脏读，可重复读再防不可重复读，串行化防不等价串行的并发结果。
- ⚫ **易混易错**：标准可重复读仍可允许幻读，具体DBMS可更强；串行化不表示物理上只运行一个事务。

### WAL与恢复

- 🔴 **核心知识**：先写日志（WAL）要求更新日志先于对应数据页落盘，提交确认前相关日志稳定保存。
- 🔵 **方法与例题**：简化UNDO/REDO模型：T1把A10改20且提交，T2把B5改8未提交；故障恢复需保证A20、撤销B为5。
- ⚫ **易混易错**：日志含撤销/重做信息及事务状态；检查点不等完整备份，介质坏损通常需备份加日志。

### 冲突优先图判串行化

- 🔴 **核心知识**：不同事务、同数据项、至少一个写构成冲突；按先后从Ti向Tj画边。
- 🔵 **方法与例题**：r1(X),w1(X),r2(X),w2(X)得T1→T2，无环可串行化为T1,T2；再有T2→T1则成环。
- ⚫ **易混易错**：读读不冲突；有环说明不满足冲突可串行化，不等于已经发生死锁。

### 两段锁的首次解锁

- 🔴 **核心知识**：两段锁（2PL）增长阶段可取锁不解锁，第一次解锁后进入收缩阶段，不再取新锁。
- 🔵 **方法与例题**：锁A→锁B→解A→锁C，最后锁C违规；严格2PL还把X锁保留至事务结束。
- ⚫ **易混易错**：2PL保证冲突可串行化但可能死锁；多版本快照读不能机械按传统S/X阻塞关系判断。

## 第9章 数据库安全性

### 认证、授权与审计

- 🔴 **核心知识**：认证确认身份，授权授予可做操作，审计记录实际行为；安全防未授权访问，完整性防非法/不相容数据。
- 🔵 **方法与例题**：GRANT赋权限、REVOKE收权限；角色汇集权限，视图限制暴露范围，参数化查询把值与命令分开。
- ⚫ **易混易错**：加密不替代授权，备份不替代访问控制；给应用最小权限，审计记录也需保护。

### 事实表的粒度与维度汇总

- 🔴 **核心知识**：粒度说明事实表一行代表什么，度量是金额等可分析值，维度描述日期/地区/商品；维表提供名称及层级。
- 🔵 **方法与例题**：三笔1月销售北区10/20、南区5：月合35、北区30；日期维映射月份后分组，取北区为切片，再按日看为下钻。
- ⚫ **易混易错**：先统一单位和粒度，不能把月合计35再与三笔一起相加；金额可加不等平均单价也可加，汇总不能替代业务事务。
