# C与Python程序设计：重点与易错

## 第1章 程序设计与算法
### 算法、流程与执行
- 🔴 **核心知识**：算法必须有确定步骤、有限结束并产生输出，顺序、选择、循环可组合表达控制流程；程序是算法在具体语言和运行环境中的实现。
- 🔵 **方法与例题**：求最大值先用首元素初始化，再逐项比较并更新；写程序前先列输入、输出、状态变量和终止条件，再把每一步翻译成语句。
- ⚫ **易混易错**：流程图画得通不代表边界正确；空输入、单元素和重复最大值都要先约定，不能用“代码能运行”代替算法正确性证明。

### 编译、解释与程序错误
- 🔴 **核心知识**：编译把源程序转换后再执行，解释器逐步处理源码或中间表示；语法错误阻止正常翻译，运行错误在执行时出现，逻辑错误产生错误结果。
- 🔵 **方法与例题**：程序崩溃先读取错误位置和异常类型，结果不对则用最小输入逐句跟踪变量；断点、打印和单元测试分别帮助观察状态与复现边界。
- ⚫ **易混易错**：C与Python的实现方式不能只凭语言名称断言；没有报错不等于没有逻辑错误，修复表面症状前要先找最早偏离预期的状态。

## 第2章 数据类型、变量与常量
### 类型、变量与转换
- 🔴 **核心知识**：C变量声明后类型确定，大小和范围受实现影响；Python名字绑定对象且可重新绑定。隐式与显式转换都可能改变精度、符号或可表示范围。
- 🔵 **方法与例题**：判断表达式先写出每个操作数类型，再执行转换和运算；Python中 int('12') 得整数，C中用 sizeof 查看本实现类型大小。
- ⚫ **易混易错**：不能假定所有平台 int 都是固定字节；浮点是有限精度近似值，不宜直接严格判等，窄化转换和有符号溢出尤其要检查。

## 第3章 运算符与表达式
### 运算符、除法与短路
- 🔴 **核心知识**：表达式求值先看括号、类型和优先级；逻辑与或会短路，位运算逐位处理整数。C整数除法向零截断，Python `/` 得浮点、`//` 向下取整。
- 🔵 **方法与例题**：7/2 在现代C整数环境为3，Python 3中为3.5；-7//2 为-4。复杂题按括号分层写中间值，短路后未执行的部分不求值。
- ⚫ **易混易错**：C中 `0<x<10` 不能表达数学区间；不要强算含未定序修改的表达式，Python 的 and/or 还可能返回操作数对象而非布尔值。

## 第4章 顺序结构与输入输出
### 输入输出与顺序跟踪
- 🔴 **核心知识**：顺序结构按控制流逐句改变状态；输入文本必须解析成目标类型，输出格式要与值匹配，读取失败和文件结束都属于程序必须处理的状态。
- 🔵 **方法与例题**：Python `input()` 返回字符串，先转 `int` 才能数值相加；C中 `scanf("%d", &n)` 需格式与地址类型匹配，跟踪题逐句记录变量新值。
- ⚫ **易混易错**：提示文字不改变输入类型；把旧值和新值混在一行心算容易出错，C格式符或地址错误可能导致未定义行为而非稳定的错误答案。

## 第5章 选择结构
### 条件与多分支
- 🔴 **核心知识**：if/else 按条件选择路径，多分支按顺序匹配；设计时要检查条件是否互斥、是否覆盖所有情况，并明确区间端点归属。
- 🔵 **方法与例题**：成绩分档应先判断 `>=90` 再判断 `>=60`；先写边界表并用59、60、89、90测试，可快速发现顺序或等号错误。
- ⚫ **易混易错**：C中赋值 `=` 与比较 `==` 不同；缩进、花括号和 else 归属会改变流程，switch 的 case 若无 break 可能继续落入后续分支。

## 第6章 循环结构
### 循环状态与边界
- 🔴 **核心知识**：循环由初始化、继续条件、循环体和更新组成；break 结束最近一层循环，continue 跳过本轮剩余语句，嵌套循环要分别计数。
- 🔵 **方法与例题**：手算时列“轮次、条件前变量、执行后变量”；`range(1,5)` 产生1到4，C的 `for(i=1;i<=4;i++)` 与其累加结果相同。
- ⚫ **易混易错**：执行次数不等于循环结束后的变量值；while 中 continue 若越过更新会死循环，边界题必须测试零次、一次和最后一次迭代。

## 第7章 函数与模块化程序设计
### 函数、参数与返回
- 🔴 **核心知识**：函数用参数接收输入并通过返回值或受控副作用给出结果；C按值传参，传入指针值才能间接修改调用者对象，Python传递对象引用的绑定。
- 🔵 **方法与例题**：C交换两个整数需传地址并解引用；Python列表传入后 append 会改变同一对象，但把形参重新绑定到新列表不会替换调用者名字。
- ⚫ **易混易错**：打印结果不等于返回结果；实参与形参是不同名字，默认参数、可变对象和指针副作用都应从“修改了哪个对象”判断。

### 作用域、递归与模块化
- 🔴 **核心知识**：作用域决定名字可见位置，生命周期决定对象存在时段；递归函数必须有可达终止条件，并让每次调用把问题缩小，模块按职责组织接口。
- 🔵 **方法与例题**：计算阶乘时先处理 n=0，再返回 n×fact(n-1)；画调用栈可看到每层参数和返回位置，验证问题规模是否持续减小。
- ⚫ **易混易错**：局部变量不会自动修改同名全局变量；递归缺终止或规模不变会耗尽栈，模块化也不是简单把长程序随意切成多个文件。

## 第8章 数组、字符串与Python组合数据
### C数组与字符串
- 🔴 **核心知识**：C数组连续存放同类型元素，下标从0开始；字符串是以空字符结尾的字符数组，数组传参时常退化为指向首元素的指针并需另传长度。
- 🔵 **方法与例题**：长度为 n 的数组合法下标是0到n-1；`strlen` 统计终止空字符前的字符数，字符数组容量还要为 `\0` 留一格。
- ⚫ **易混易错**：数组越界不保证立即报错；函数形参处的 `sizeof` 不能得到原数组总字节数，字符串复制还要检查目标容量。

### Python列表、元组、字典与集合
- 🔴 **核心知识**：列表可变且有序，元组不可变，字典按键映射值，集合保存不重复元素；切片产生新容器，但浅拷贝仍可能共享嵌套对象。
- 🔵 **方法与例题**：`b=a` 让两个名字指向同一列表，b.append 会影响 a；`b=a.copy()` 只复制外层。按需求选择顺序、键查询或去重结构。
- ⚫ **易混易错**：字典成员测试默认检查键，集合无下标顺序；元组内部若含列表，列表仍可变，浅拷贝也不等于递归复制全部数据。

## 第9章 C指针、结构体与文件
### C指针与地址

![C指针与地址图解](../media/program_pointer_card.svg)

- 🔴 **核心知识**：指针变量保存地址，`&` 取得对象地址，`*` 解引用访问所指对象；指针加一按所指类型大小移动到下一个元素。
- 🔵 **方法与例题**：若 p 指向 int 数组 a[0]，p+1 指向 a[1]；画出变量格、地址和箭头后，再推演 `*p`、`p++` 与 `(*p)++` 的区别。
- ⚫ **易混易错**：未初始化、空悬、越界和已释放指针都不能解引用；返回局部自动变量地址会失效，指针本身的地址与它保存的地址不同。

### C结构体
- 🔴 **核心知识**：结构体把不同类型字段组合成一个记录，可定义变量、数组和指针；对象成员用点号访问，结构体指针成员用箭头访问。
- 🔵 **方法与例题**：学生记录含学号、姓名、成绩，排序时明确交换整个结构体或索引；`p->score` 等价于 `(*p).score`，括号不可省错。
- ⚫ **易混易错**：结构体赋值与指针共享不是一回事；内存可能因对齐出现填充，含字符数组的字段复制还要遵守容量和终止符规则。

### C文件与资源管理
- 🔴 **核心知识**：文件操作包括打开、读写、检查状态和关闭；文本与二进制模式语义不同，动态内存和文件句柄都应在所有退出路径上释放。
- 🔵 **方法与例题**：`fopen`后检查NULL并按读取返回值循环；超大文件流式读并保留块尾残词，中间映射仍过大时分区落盘再归并。
- ⚫ **易混易错**：`feof` 只有尝试读取到末尾后才成立；忘记关闭、重复释放或使用释放后的内存都会造成资源或正确性问题。

## 第10章 Python异常、模块与文件
### Python异常、模块与文件
- 🔴 **核心知识**：try/except 按异常类型处理失败，finally 负责无论成败都要执行的清理；with 管理资源生命周期，文本文件读写需明确编码。
- 🔵 **方法与例题**：用户输入转整数可捕获 ValueError 并重试；`with open(path, encoding='utf-8')` 在退出代码块时自动关闭文件。
- ⚫ **易混易错**：捕获所有异常后静默忽略会隐藏缺陷；文件不存在、权限不足和解码失败原因不同，finally 中 return 还可能覆盖原返回值。

## 第11章 C与Python程序模型比较
### C与Python语义比较
- 🔴 **核心知识**：迁移同一算法时应逐项核对类型、整数除法、下标、参数、容器、内存和异常语义；正确迁移保留行为目标，而非逐字替换语法。
- 🔵 **方法与例题**：C数组常需另传长度，Python列表可用 len；求中间下标时两者都要整数结果，但Python `/` 会产生浮点值，应选择 `//`。
- ⚫ **易混易错**：Python负下标有定义，C负下标访问没有同样规则；自动内存管理也不代表没有资源泄漏，外部文件和网络连接仍需及时关闭。
