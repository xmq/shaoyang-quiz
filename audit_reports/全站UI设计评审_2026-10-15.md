# 全站 UI 设计评审（2026-10-15）

评审身份为独立 UI 设计代理，使用浏览器模拟视口，不代表真人设计师、真实学生或真机体验。范围为首页、刷题入口、作答与反馈、讲义、重点，以及配图预览。

## 参考与问题

参考 [PhotoSwipe 的缩放规则](https://photoswipe.com/adjusting-zoom-level/)、[交互选项](https://photoswipe.com/options/) 和 [Medium Zoom](https://github.com/francoischalifour/medium-zoom) 的阅读图片预览方式。PhotoSwipe 的 fit 模式按视口宽高适配，初始不超过图片原尺寸，适合本系统的讲解 SVG。

改造前实际浏览模拟电子技术共射图：1280×900 下正文为 520×819，预览为 800×1260，默认放大导致下半图需要滚动。390×900 下预览图 332×523，但固定弹窗底部留下大块空白，标题与百分比工具条占两行。图片视图只按宽度计算初始倍率，重置再次回到默认放大状态。

全站同时存在首页与刷题青绿色、讲义蓝色、重点整段纯红蓝加粗、文字代替图标、普通卡片多层阴影等不一致。刷题下拉课程名附带题量，手机会截断；桌面题量上下重复。

## 实施

- 新增 ui.css 作为共同视觉系统：纸面背景、深色正文、单青绿操作色、12px 卡片圆角、常规边框代替叠加阴影，并统一暗色模式。
- 首页保留课程选择与学习状态，统一课程图标与底部四个入口的 SVG 图标。桌面三列、手机单列，分类保持一排可横向滚动。
- 刷题入口取消“大卡片套小卡片”，保留一个主要练习入口，其他入口使用轻边框；课程名独立展示，进度在练习范围处显示。
- 重点正文恢复常规深色，仅核心、方法、易错的小标签分别着色；章节与知识点通过字号、间距和细分隔线分层。
- 正文图片保持各自比例与自然尺寸，仅限制最大宽高；图片外框随内容收缩。预览交互由本地 PhotoSwipe 实现，打开适应屏幕，支持放大、恢复与关闭，不使用固定巨大内容面板。

## 验证

自动化与截图覆盖 390×844、1280×900、844×390 三种视口，明暗两种主题，每种包含首页、刷题入口、题目、作答反馈、正文图、预览、放大后、重点共 8 种状态，合计 48 次页面状态检查。无脚本错误、页面横向溢出；课程分类筛选可用。模拟电子技术首题为简答，作答反馈检查跳过简答进入有选项题，不以测试脚本假定所有课程首题题型。

图片另验证初始完整入屏、放大后恢复初始比例、Esc 关闭、浏览器返回关闭，关闭后 URL 与阅读位置保留。人工查看了首页手机/桌面、桌面刷题入口、手机暗色答题反馈、重点手机、共射图桌面、手机暗色预览与横屏正文截图。桌面共射图恢复为约 400×630 自然比例，手机预览完整且可继续放大。

实际看图后发现删除旧主题让分类标签回落成两列，已在共享 CSS 明确 flex 与不换行；补齐首页卡片 padding 与结构声明，避免依赖已删除主题；语义标签按真实 recall-answer 嵌套修正。桌面刷题顶部重复 mini-stat 已隐藏。

最后重建后再次查看首页 390px 与桌面 1280px 的讲义、重点实际截图：四个课程分类保持一排，首页卡片无多余内层留白；桌面左侧目录、章标题、小节标题和正文层级清楚，重点仅三个标签着色，正文未整段染色。此复看通过后未留下待修正的 UI 阻塞项。

截图与机器结果保存在操作系统临时目录 `zhijie-ui-final`，不作为产品静态资源提交。验证不覆盖所有知识点内容正确性、所有设备型号或真实 Android 手势。

## 使用边界

横屏 844×390 的正文图会因高度限制缩小，文字细节应点击预览查看；这是完整比例与阅读布局之间的取舍。该视口为浏览器模拟，不替代横屏真机验证。普通滚动保留浏览器行为；缩放与拖动由成熟图片库负责，不另造系统返回手势。
